# DeepSeek V4.1 Flash on 2× Strix Halo — disk streaming + TP2/RDMA design

Status: **design only.** No GPU or implementation until the user allows it  
(benchmark may be live). Goal: a coherent design for **streaming weights from  
NVMe** while using the existing **two-host RDMA collective** stack.

---

## 1. Problem statement

| Constraint | Value |
| --- | --- |
| Hosts | 2 × Strix Halo, **128 GiB** unified each (~**240 GiB** usable together) |
| Model | DeepSeek **V4.1 Flash**: **763B** params, FP8 official (~**763 GB**) |
| Active / token | ~**8B** prefill / ~**16B** decode (MoE: **6+1** experts of **384**) |
| Today in gufo | V4 Flash only, **resident**, **no TP**, **no weight streaming** |

**Resident TP2 cannot hold V4.1.** The only realistic two-host story without  
more machines is: **most weights on NVMe**, **hot working set in RAM/GPU**,  
optionally **shard the expert pool across hosts** (TP-style).

---

## 2. Architecture recap (what we reuse)

### 2.1 Flash-Next TP2 (collective + mirror)

- **World size 1 or 2.**
- **Split:** expert FF intermediate (quant-block aligned), attention/GDN heads.
- **Same experts on every rank:** each rank computes **every selected expert**  
  on **its** FF slice; MoE **all-reduce** sums partials  
  (`tp_partition.hpp`: ranks must not wait on “who got more experts”).
- **All-reduce:** after mixer + MoE; F32 `rows × hidden`; verbs **3×48 MiB**  
  windows (`verbs.cpp`); prefill batch must fit one window.
- **Rank 1:** mirrored executor (`TpMirroredRunner` / `TpExecutor`);  
  component cache **off**; same binary/sha on both hosts.

### 2.2 What does **not** exist in gufo

- No **weight streaming** (SSD → device) in production paths.  
  DS4 uses **managed memory for KV paging only** (`rocm_graph.cpp`);  
  upstream **explicitly omitted** SSD weight streaming (`UPSTREAM.md`).
- No V4.1 runtime (CED, CSA2, **VQ experts**, Engram, vision, new encoding).

### 2.3 Primary reference implementation: **ds4-dfm-rs**

The working engine for the VQ artifact is **not** stock llama.cpp. It is:

## 3. Streaming design

### 3.1 Placement tiers

| Tier | Contents | Where |
| --- | --- | --- |
| **T0 Device** | Dense/attention/embeddings (or their TP shards), **hot expert cache**, active KV/CSA2, small scratch | GPU/HBM-mapped unified |
| **T1 Host pin** | Staging buffers, IO completion rings, optional page-cache hot experts | Pinned host (`hipHostMalloc` / registered) |
| **T2 Page cache** | Recently read expert blocks (OS) | System RAM after weights file |
| **T3 NVMe** | Full quantized GGUF / expert-major shards | Local SSD on **each** rank |

**Rule:** T0+T1 must fit in ~**40–70 GiB** per host (leave room for KV + OS).  
Everything else is T3 with T2 as opportunistic cache.

### 3.2 What stays resident vs streams

| Component | Policy | Why |
| --- | --- | --- |
| Token embedding, LM head (or sharded) | **Resident** | Every token |
| Attention / CSA2 projections, norms, routers | **Resident** | Every layer |
| **Shared expert** | **Resident** (or high-priority pin) | Always active |
| **Routed experts (384)** | **Stream** (hot LRU cache) | Only 6/token |
| **Engram (196B)** | **Stream by page** (token-hash → row) | Sparse lookup; huge |
| Vision encoder | Resident if used; **omit** for text-only v1 | Optional |
| KV / CSA2 index | Resident budget (compressed); overflow → managed or host | Not weights |

### 3.3 Storage layout (on disk)

Prefer **expert-major** shards so a cache miss is one sequential-ish read:

```
model.gguf
  dense/                 # resident path
  experts/e{layer}.{expert_id}.bin   # or packed groups of experts
  engram/page_{n}.bin
  index.json             # offsets, quant block size, checksums
```

- Align each expert blob to **quant block** and **page size** (4 KiB) and  
  optionally **NVMe optimal read** (64–256 KiB).
- Optional **TP-aware packaging:** pack expert as  
  `[ff_begin:ff_count]` **per rank** so each host only stores/downloads **half**  
  the expert bytes (see §5).

### 3.4 Device expert cache

```
struct ExpertSlot {
  uint32_t layer, expert_id;
  uint32_t use_tick;          // LRU
  DeviceBuffer weight;        // this rank's FF shard or full expert
  enum { Free, Loading, Ready } state;
};
```

- **Capacity:** configurable, e.g. `N` slots × `expert_bytes` ≈ **8–32 GiB**.
- **Addressing:** router output → set of 6 expert IDs → `GetOrLoad(layer, id)`.
- **API (conceptual):**
  - `Prefetch(layer_span, expert_ids)` — async from T3/T2 → T1 → T0  
  - `WaitReady(layer_span, expert_ids)` — before MoE GEMM  
  - `Touch(layer, id)` — LRU  
  - `EvictDirty` — only if we ever fine-tune (inference: read-only, no writeback)

### 3.5 Async I/O pipeline

```
Router (top-k)
    │
    ├─► ExpertCache.Prefetch  ──► io_uring / thread pool ──► pread(MiB)
    │         │                              │
    │         ▼                              ▼
    │   pinned staging (double-buffer)   page cache hit?
    │         │
    │         ▼
    │   async H2D (hipMemcpyAsync on dedicated stream)
    │
    └─► (overlap) rest of layer: attention already done
              │
              ▼
         WaitReady → MoE GEMM → all-reduce (if TP)
```

**Double-buffer staging:** while GPU computes layer *L* MoE, prefetch  
layer *L+1*’s experts (lookahead 1–2 layers).  
**Stream isolation:** I/O + H2D on a **side stream**; compute stream waits  
with events only when the slot is needed.

### 3.6 Cache policy

| Policy | Setting |
| --- | --- |
| Replacement | LRU (or LFU with decay) |
| Pin set | Shared expert + current batch’s 6 experts |
| Prefetch | Router top-k **before** GEMM; optional next-layer heuristic (same experts often recur in code paths — measure, don’t assume) |
| Admission | Reject load if free slots < batch demand; fall back to **sync** load (correct, slower) |
| Failure | Missing/corrupt blob → request error, not hang |

### 3.7 KV / CSA2 / Engram

| State | Approach |
| --- | --- |
| KV (FP4 ~890 B/token) | Resident up to context budget; if tight, **host managed** (pattern exists in DS4) — **not** NVMe per token |
| CSA2 indices | Resident small buffers; recompute or persist with session snapshots |
| Engram pages | Same store as experts: hash(token) → page; hot pages pinned; cold pages stream |

### 3.8 Quant / decode

- Stream **already-quantized** expert blocks (IQ2/Q4/FP8 as packaged).  
- No re-encode on the fly.  
- TP FF slice must be **cut on quant-block boundaries** (same rule as Qwen  
  `tp_partition`).

## 4. Single-host streaming (v1) — prove the store first

Before TP2:

1. Resident dense + **full** expert stream from local NVMe.  
2. Measure: cold vs warm tok/s, NVMe MB/s, cache hit rate, T0 occupancy.  
3. Target: decode not I/O-bound at a stated tok/s (e.g. ≥10–20  tok/s) with  
   realistic batching.

**Exit criteria:** stable tokens with empty page cache; no deadlock; memory  
within budget.

## 5. Streaming × TP2/RDMA (v2 design)

Two complementary ideas; use **both**.

### 5.1 Compute TP (already proven on Flash-Next)

Keep Qwen’s rule:

> Every rank runs the **same** selected experts on a **partition of the FF  
> intermediate**; **all-reduce** sums partials.

- Router runs on **rank 0** (or both from identical logits) so **top-k IDs  
  match**.  
- Rank 1 never chooses a different expert set (that would desync collectives  
  *and* streaming).

### 5.2 Storage TP (halve NVMe and hot RAM)

| Mode | Each rank stores/streams | Hot cache | All-reduce |
| --- | --- | --- | --- |
| **Mirror** | Full expert blob | Full experts | After MoE (partial = full expert result — wasteful) |
| **Shard storage (recommended)** | **Only `[ff_begin:ff_count]`** of each expert | Half-size slots | After MoE (partial FF → sum) — **same as Qwen** |
| **Shard experts (IDs)** | Disjoint expert IDs | Different slots | Needs **all-to-all** of activations — **avoid** (not in verbs stack) |

**Do not shard expert IDs across ranks** for v1–v2: that requires exchanging  
token→expert activations (all-to-all), which the current verbs layer does  
not implement. **Shard the FF intermediate**, stream **local rows only**.

Bytes saved: expert traffic ≈ **½** vs mirror.

### 5.3 Synchronization of streams

```
Both ranks: identical router → {e1..e6}
Rank r: Prefetch(own FF shard of e1..e6) from local NVMe
Both: WaitReady → MoE partial → AllReduce → next layer
```

| Hazard | Mitigation |
| --- | --- |
| One rank slower I/O | All-reduce **blocks both**; design prefetch so **p99** load << compute budget; optional **I/O deadline** + retry |
| Different top-k | Force deterministic router; rank0 ships expert-ID list in the **same instruction** as draft/batch metadata if needed |
| Window vs expert bytes | Expert loads are **not** all-reduce payloads; only FF partials go through 48 MiB windows |
| Prefill batch size | Unchanged: partial must fit `MaxPartialBytes` (re-derive for V4.1 hidden size) |

### 5.4 Overlap with verbs

Ideal schedule per layer:

```
        ┌── attention / dense (resident) ──┐
host:   │  prefetch experts L+1            │
        └──────────────┬───────────────────┘
                       ▼
              MoE GEMM (L) on ready slots
                       ▼
              all-reduce partial (verbs, 3 windows)
                       ▼
              residual combine
```

- Prefetch of L+1 overlaps **attention of L** and **all-reduce of L−1**.  
- Never issue expert H2D on the **compute stream** that also runs all-reduce  
  kernels without events (avoid serialize-on-copy).

### 5.5 Control plane (mirror)

Reuse Flash-Next **instruction mirror**, extended:

| Instruction | Extra payload for streaming |
| --- | --- |
| `kSingle` / batch | Expert-ID list **or** rely on identical router from same logits |
| Prefill / decode | As today + implicit expert set from tokens |
| Snapshot | Expert cache is **ephemeral** — **do not** snapshot device expert slots; restore = cold cache |
| Rank1 readiness | Both ranks report `expert_cache_ready` before first token |

**Component cache / disk KV cache:** still **not** used for TP2 mirror  
(`UsesComponentCache()==false`). Expert NVMe is **weights**, not continuation  
snapshots.

### 5.6 Failure modes

| Symptom | Likely cause |
| --- | --- |
| `verbs all-reduce timed out` | Rank stuck in `WaitReady` (disk) while peer already in collective — **prefetch too late** or rank death |
| Empty completion | Rank0-only path / desync (same class as old TP2 bugs) |
| tok/s collapse cold | Cache too small or no lookahead |
| OOM | T0 + KV over budget; shrink expert slots |

**Hardening:** watchdog on `WaitReady` (e.g. fail request after N ms with  
clear error, never leave peer in verbs forever). Aligns with existing TP2  
“collective sequence must match” rule — **disk wait must not replace a  
collective with an infinite host block**.

### 5.7 Memory budget sketch (per host, illustrative)

| Item | GiB |
| --- | ---: |
| Dense + attention TP shard | 15–30 |
| Expert cache (sharded) | 16–32 |
| Engram hot pages | 4–8 |
| KV (moderate context) | 5–20 |
| Staging + verbs windows | ~1 |
| OS / HIP overhead | ~10–15 |
| **Total** | **~50–100** (fits 128) |

On-disk model: full quant (100s of GB) on **each** host’s NVMe (or shared  
NFS — **prefer local NVMe**).

### 5.8 Bandwidth sanity check

Assume **2-bit** expert-heavy path, decode ~15 tok/s, **6** experts/layer,  
**40** layers, active expert bytes/layer ~**X** MB (depends on FF and quant).

Rough expert read rate:

```
bytes/s ≈ tok/s × layers × active_experts × bytes_per_expert_slice
```

If `bytes_per_expert_slice` (rank shard) is ~**2–8 MB**, order of magnitude  
is **low GB/s** — achievable on modern NVMe **if** requests are sequentialized  
enough and prefetch hides latency. **Must be measured** on this hardware with  
the real GGUF; do not trust the placeholder MB numbers.

Flash-Next USB4 ~**37 Gb/s** aggregate is for **partials**, not NVMe.

## 9. Verification plan (later)

1. **Store unit:** random expert fetch correctness vs file checksum.  
2. **Cold start:** empty page cache → first request still completes.  
3. **Warm steady state:** hit rate and tok/s plateau.  
4. **Single-host quality:** greedy sample vs offline reference (same quant).  
5. **TP2:** same binary sha; ≥5 requests; one deep/agent-style prompt;  
   watch `/metrics` concurrency; no verbs timeout.  
6. **Fault:** kill NVMe file mid-run → clean error, no hung peer.

## 10. Bottom line

1. **V4.1 does not fit** two 128 GiB hosts as pure resident FP8 / large GGUF.  
2. **Baekpica/YoungAi 1017 VQ (~114 GB base)** fits **one** host; **Engram (~203 GB) streams from NVMe**.  
3. **Working reference implementation:** **https://github.com/Baekpica/ds4-dfm-rs** (Rust + CUDA; `docs/deepseek41-flash.md`, port plan, **`io_uring` Engram**, VQ kernels). Gufo studies and re-implements the contract in HIP; TP2 is gufo-only.  
4. **Always** ship **single-host** then **TP2** (FF shard + verbs all-reduce + mirror). Expert storage TP optional; no expert-ID all-to-all.  
5. Phase 0–2 = **read ds4-dfm-rs**, pin artifact, single-host Engram stream, then TP2. No GPU until the user allows it.
